# PasswordEncoder를 이용한 비밀번호 평문 저장 개선

## 문제 상황
- 회원가입 시 사용자가 입력한 비밀번호가 별도의 변환 없이 DB에 평문으로 저장되고 있었음
- 로그인 시에도 입력한 비밀번호와 DB에 저장된 비밀번호를 문자열로 직접 비교하고 있었음
- DB 데이터가 노출될 경우 회원의 실제 비밀번호가 그대로 확인될 수 있는 보안 문제가 있었음

## 원인
- 초기 회원가입과 로그인 기능 구현에 집중하면서 비밀번호를 일반 문자열 데이터와 동일하게 처리함
- 비밀번호 저장과 검증을 담당하는 별도의 인코딩 로직이 적용되어 있지 않았음
- 단방향 해시로 저장된 비밀번호의 올바른 비교 방법에 대한 고려가 부족했음

## 해결 방법
- Spring Security Crypto에서 제공하는 `PasswordEncoder`를 Bean으로 등록함
- 회원가입 시 `encode()`를 사용하여 입력된 비밀번호를 단방향 해시값으로 변환한 뒤 DB에 저장하도록 수정함
- 로그인 시 비밀번호를 문자열로 직접 비교하지 않고, `matches()`를 사용하여 입력한 비밀번호와 저장된 해시값을 비교하도록 변경함
- 회원정보 수정 과정에서도 변경된 비밀번호가 평문으로 저장되지 않도록 `PasswordEncoder`를 적용함

## 배운 점
- 비밀번호는 복호화할 필요가 없는 데이터이므로 평문이나 양방향 암호화가 아닌 단방향 해시 형태로 저장해야 한다는 것을 배웠습니다.
- 같은 비밀번호를 `encode()`하더라도 매번 다른 해시값이 생성될 수 있으므로, 인코딩된 값을 직접 비교하지 않고 `PasswordEncoder.matches()`를 사용해야 한다는 것을 알게 되었습니다.
- 비밀번호 저장 방식을 변경할 때는 회원가입뿐만 아니라 로그인, 회원정보 수정, 초기 데이터 등 비밀번호가 사용되는 전체 흐름을 함께 점검해야 일관된 처리 방식을 유지할 수 있다는 것을 배웠습니다.
