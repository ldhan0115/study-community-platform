# 회원 정보 수정 시 '본인 데이터' 중복 검증 예외 발생 해결

## 문제 상황
- 사용자가 마이페이지에서 비밀번호 등 일부 정보만 변경하고 [수정] 버튼을 눌렀을 때, `IllegalStateException("동일한 NICKNAME이 존재합니다.")` 예외가 터지면서 정보 수정이 실패하는 버그 발생

## 원인
- 회원가입(Join) 시 사용하던 중복 검증 로직을 정보 수정(Edit) 시에도 동일하게 재사용함
- DB에서 닉네임 중복 여부를 조회할 때, '타인이 사용 중인 닉네임'뿐만 아니라 '현재 로그인한 사용자의 기존 닉네임'까지 중복으로 인식하여 예외를 발생시킴

## 해결 방법
- **로직 분리:** 정보 수정 전용 검증 메서드(`validateDuplicateMemberForEdit`)를 분리하여, 폼에서 넘어온 데이터와 기존 회원의 데이터가 '다를 경우에만' 중복 검사를 하도록 방어 로직 추가
- **성능 최적화:** 기존에는 중복 확인을 위해 `findBy~` 메서드로 엔티티 객체를 통째로 조회했으나, 이를 Spring Data JPA의 `existsBy~` 메서드로 리팩토링하여 객체를 메모리에 올리지 않고 `EXISTS` 쿼리만 날려 boolean 값만 반환받도록 성능을 개선함

## 배운 점
- 데이터 생성(Create)과 수정(Update) 시의 검증 로직은 비슷한 듯 보이지만, '기존 데이터'라는 맥락(Context)이 추가되므로 로직을 명확히 분리해야 한다는 점을 배웠습니다.
- Spring Data JPA가 제공하는 메서드 네이밍 규칙(`existsBy`)을 활용하여 단순한 기능 구현을 넘어 가독성과 쿼리 성능(메모리 낭비 방지)까지 최적화할 수 있음을 경험했습니다.
