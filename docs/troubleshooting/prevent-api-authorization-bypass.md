# API 강제 호출을 통한 권한 우회 및 타인 데이터 조작 방지

## 문제 상황
- 스터디 신청 상태(승인/거절) 변경 버튼을 스터디장에게만 보이도록 화면 단(HTML)에서만 숨김 처리함
- 악의적인 사용자가 Postman 등의 툴을 이용해 API를 강제로 호출할 경우, 본인이 스터디장이 아님에도 남의 스터디 신청 내역을 임의로 조작할 수 있는 심각한 인가(Authorization) 취약점 발견

## 원인
- 비즈니스 로직(Controller) 계층에 요청을 보낸 사용자가 해당 작업을 수행할 '권한'이 있는지 확인하는 서버 단의 인가(Authorization) 처리 로직이 누락됨

## 해결 방법
- 화면 단 처리를 넘어 컨트롤러 단계에서 권한 검증 계층을 추가
- 현재 접근한 사용자의 세션 ID와 데이터 소유자(스터디장)의 ID를 직접 비교하여, 불일치할 경우 에러 로그를 남기고 접근을 원천 차단하도록 보안을 개선함

## 배운 점
- '프론트엔드(화면)에서의 버튼 숨김'은 단순한 UX 개선일 뿐, 결코 보안(인가) 처리가 될 수 없음을 명확히 이해했습니다.
- 클라이언트의 요청은 언제든 조작될 수 있으므로, 핵심 데이터의 수정/삭제가 일어나는 API 서버(Controller, Service) 단에서 반드시 사용자 권한 검증 로직이 동반되어야 한다는 백엔드 개발자의 기본 수칙을 확립했습니다.
